# 顧問公司類比

2026-10-08 的討論紀錄。問題是：把 agent 想成被派駐到企業協助轉型的顧問（例如 Andersen Consulting、McKinsey），像不像？顧問模式的成敗取決於什麼？這份討論與 [industry-practices-and-risks.md](industry-practices-and-risks.md) 一起促成了 [D2](../10-decision-log.md)。

下面的成敗因素是管理實務上的普遍共識，不是特定研究的統計結論。

## 兩種顧問模式

| | 策略顧問（McKinsey 型） | 實作顧問（Andersen／Accenture 型） | 最初構想的 agent |
|---|---|---|---|
| 主要產出 | 診斷和建議 | 把系統做出來 | 兩者都可以 |
| Domain knowhow | 少，靠通用框架 | 少，靠方法論與技術能力 | 少，靠 CI/CD 觀念與 scripting 能力 |
| 權威從哪裡來 | 高層的委託 | 合約與高層的委託 | 沒有 |
| 對話對象 | 高層 | 中階主管與執行團隊 | 第一線工程師 |
| 期限 | 有，結束就離開 | 有，系統上線後交接 | 無限期常駐 |

**相似處：** 核心前提一樣，都假設通用方法論加上外部視角可以彌補 domain knowhow 的不足。

**關鍵差異：**
- 顧問能推得動，靠的是背後 sponsor 的權威，不是方法論。最初構想的 agent 直接面對工程師，背後沒有任何人。
- 顧問會離開，成敗取決於離開後改變是否還在。Agent 不會離開，這是優勢，也可能讓團隊永遠依賴它。

## 顧問模式的成敗因素

1. **Sponsor 是否有實權，而且持續關注。** 最常見的失敗是 sponsor 開完 kickoff 就消失，基層很快看出「老闆其實不在乎」。
2. **先診斷，再開藥方。** 好的顧問頭幾週在訪談和觀察，找出真正的痛點。失敗的顧問直接套 template（cookie-cutter solution）。沒有 domain knowhow 的 agent 最容易掉進這個陷阱，因為它最擅長背出「標準 CI/CD 實踐」。
3. **解決的是基層的痛，還是只有高層的痛。** 基層覺得「這幫我省事」才會配合。
4. **有沒有內部的對口人。** 由內部的人把通用框架翻譯成在地做法，並在顧問離開後承接。
5. **能力有沒有轉移。** 失敗的案子讓客戶產生依賴；成功的案子讓客戶自己長出能力。
6. **前期有沒有看得見的 quick win。** 沒有早期成果，懷疑的聲音很快就會蓋過一切。

## 員工的排斥

會有，但不是大多數人都在排斥，而且排斥本身是有用的資訊。

- **排斥的分布不平均。** 新做法擴散時，少數人主動擁抱，少數人堅決反對，大多數人觀望。觀望的人看的是身邊同事用了之後有沒有變好。不必說服所有人，先讓願意的人成功。
- **人排斥的是「被改變」，不一定是改變本身。** 自己選的改變與被強加的改變，反應完全不同。
- **排斥常常是理性的。** 可能代表成本真的落在他身上，或做法確實不適合他的情境（例如 ECO 流程不能照軟體那套走）。不要把所有反對都當成心態問題。
- **歷史包袱。** 員工常把顧問看成「高層派來找人砍的」；AI agent 對應的包袱是「AI 是來取代我的」，需要正面處理。
- **AI 比人類顧問多一個劣勢。** 人看到演算法犯錯，失去信任的速度比看到人犯同樣的錯更快（Dietvorst et al., 2015, algorithm aversion）。人類顧問可以靠吃飯、閒聊修補關係，agent 沒有這種管道。

## 對設計的啟示

如果把 agent 當成一個顧問團隊來設計，需要：

- **Sponsor**：一位有實權的人。Agent 借他的權威，他定期看進度。
- **對口人**：每個試點團隊一位，最好是對 CI/CD 有興趣的工程師或 PL，判斷 agent 的建議在 IC 情境下是否合理，補上 domain knowhow 的缺口。
- **診斷期**：先觀察與訪談，產出「這個團隊的痛點」，而不是「這個 repo 違反了哪些規範」。
- **自願的試點團隊**：挑想要改變的團隊，不是問題最多的團隊。
- **出場條件**：定義什麼叫轉型完成（例如團隊自己維護 pipeline，agent 退成維運角色），避免依賴，也讓「它不會一直盯著我」成為對團隊的承諾。

Agent 也有顧問比不上的優勢：便宜、不會離開、能直接實作、有耐心、記性一致。合適的模型是**一個由人類 sponsor 背書、與內部對口人搭檔、以實作為主的顧問團隊**，而不是單獨派駐的策略顧問。這個結論後來發展成 D2 的「人定方向，AI 執行」。
