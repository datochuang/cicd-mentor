CI/CD Mentor Agent

一個自主運行的 AI agent，協助 IC 設計工程團隊把 CI/CD 與迭代式開發真正落地。方向由一位人類 PM 掌握。

第 1 部分

這個專案要達成什麼

1.1一句話說明目的

讓 IC 設計工程團隊建立並真正使用 CI/CD 與迭代式開發，成為 Agentic AI 發揮效益的地基。

AI agent 是推動與落地的執行力，不眠不休地觀察、提案、溝通、實作；一位人類 PM 決定方向、定義成功，並在理解提案後核准。

1.2為什麼是 CI/CD：它在整件事裡的位置

公司導入 Agentic AI 的最終目標，是讓 AI 的效益突破組織既有的疆界與流程限制，而不只是讓個人工作快一點。這需要一層層的地基，CI/CD 是其中技術上不可或缺的一層，也是目前最缺的一層。

公司競爭力 更快、更可靠地交付晶片
AI 效益規模化 AI 的產出能被驗證、被信任，才能交給它更多、跨團隊的工作
迭代式開發 tape-out 前的內循環（RTL、驗證、synthesis、STA）小步快跑、頻繁整合
CI/CD 每次變更自動驗證；每個交付都能說出來源版本、可以重現
本專案 由 PM 加上 AI agent，把上面這層真正建起來、讓團隊用起來
↑ 每一層都建立在下一層之上tape-out 本身不在迭代範圍內

Google 的 DORA 2025 報告把 AI 形容為放大器：它放大組織原有的優點，也放大原有的失能。沒有 CI/CD 的團隊導入 AI，放大的多半是後者。

1.3從現狀到目標狀態

目前公司 IC 設計相關的工程部門沒有 CI/CD 的觀念與實踐。下表是方向示意，具體的目標狀態由 PM 定義。

現狀目標狀態
版控的角色檔案備份工具，頂多打 label／tag唯一可信的來源，每個交付都追溯得到
變更進來之後沒人知道有沒有弄壞什麼，問題到整合時才爆發自動驗證，當天就知道結果
驗證極少數流程會觸發 sanity check每次變更跑最小的 smoke check，定期跑更完整的 regression
開發節奏各自長時間開發，後期才大整合小步提交、頻繁整合
AI 能做的事個人助理，產出難以驗證在 pipeline 中被驗證，可以放心交付更多工作
現狀

PM 問：「這份 regression 結果是根據哪一版跑的？」

「我查一下……應該是上週五 sync 的，但我 workspace 裡改過幾個檔案，tool 版本要問一下 CAD。」

目標狀態

PM 問同一個問題。

「label rx_dsp_r0.4.2，對應 CL 482113，tool 版本和重跑指令在報告第一行。」

情境為示意，label 名稱與 CL 號碼是虛構的。

1.4為什麼需要一個專案，而不只是導入工具

工程師不做 CI/CD，多半不是因為不懂，而是因為成本與好處不對等。工具買得到，這三個障礙買不到：

成本在自己，好處在別人

多寫一個 check、多維護一份 filelist，花的是自己的時間；受益的是下游、整合者和未來的自己。

時程壓力

tape-out 前任何額外的工作都會被往後推，而改善流程永遠不是最急的事。

EDA 執行昂貴

license 有限、一次模擬或 synthesis 要跑數小時，「每次變更都驗證」不像軟體那樣理所當然。

所以這個專案同時從兩端著手：

AGENT：壓低成本

先代做：寫 script、建 pipeline、提出可直接採用的修正，讓「做對的事」幾乎不花工程師的時間。

PM：提供拉力與方向

定義什麼叫成功、決定優先順序，並以組織的權威讓改變成為團隊的事，而不是 agent 的一廂情願。

1.5誰負責什麼

Agent 自主運行，受限制的是方向而不是行動。它形成的決定與方針要主動向 PM 匯報，確認 PM 真的理解之後，由 PM 核准才生效。運作細節在後續章節說明。

PM
  • 有使命感與推動的權威
  • 定義方向與成功的樣子
  • 理解提案後核准
意圖、核准 ⇄ 提案、異議、教學
AI agent
  • 不眠不休地自主運行
  • 把意圖轉化成可行的行動
  • 給 PM 整個團隊的全貌
溝通、實作 ⇄ 回饋、現況
工程團隊
  • 使用並逐步擁有 pipeline
  • 對 agent 的提案提出意見
  • repo 與工作流程的主人

1.6這個專案是什麼，不是什麼

是

  • 推動 CI/CD 落地的執行力，持續運作
  • 把 PM 的高階目標轉成具體可行的行動
  • 先替團隊把事情做好的幫手
  • 讓 PM 與團隊逐步長出自己的能力

不是

  • 設計或驗證用的 AI：它關心的是開發流程，不是 design 本身
  • 監控或考核工程師的工具
  • 一次性的稽核報告
  • 自行決定方向的 AI
  • 取代工程師

1.7成功的樣子

以下是方向示意：用團隊能不能回答某些問題、能不能自己做到某些事來衡量，而不是 agent 發現了多少問題。

  1. 1任何一份交付或結果，都說得出它根據哪個版本、用哪個 tool 版本產生
  2. 2任何人都能從乾淨的環境重現它
  3. 3變更弄壞東西時，當天就會被發現，而不是在整合時
  4. 4PM 能自己判斷 CI/CD 相關的取捨，agent 從提案者逐漸退到審核者
  5. 5團隊自己維護 pipeline，agent 退到輔助與維運的角色

待決定：具體的指標與門檻由 PM 定義；PM 由誰擔任、試點團隊與範圍也尚未決定。
