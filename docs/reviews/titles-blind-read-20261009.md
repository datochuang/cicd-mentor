**做法**：派一個乾淨 context 的 subagent，只給它三份投影片的文件標題與每頁標題（沒有圖、沒有內文），要它扮演「每天用 Perforce、不熟 CI/CD、沒參與過討論的 IC 設計主管／工程師」，回答「這些頁面的目的，光從標題看得出來嗎」。

**處理**：報告裡的建議大多採用（見下方「採用與未採用」），標題已改，文件已重建。

## 採用與未採用

- 採用：補主詞（工程師、主管、人或 agent）；拿掉只有討論過的人才懂的簡稱（轉循環、補一版、拆包、三類事、歷史）；「repo」改「depot」；「smoke check」改公司慣用的「sanity check」；「併入」改「進 depot」；總結頁改成「哪一版跑的、能不能重跑」答不出（Perforce 使用者會反駁「關於檔案的問題」）；SSOT 兩頁標成（環境）／（複本）；收斂頁點名 SSOT、CI；文件三的「owner」標成「專案 owner」。
- 未採用：原則名稱改中文（SSOT→單一來源、Self-documenting→目錄說明等）。使用者在 D4 決定原則一律用英文專有名詞；標題保留英文，頁面上另有中文註解。
- 待使用者決定（todo T20）：文件二 p4–p16 冒號前全是「問題」，13 頁下來那格沒有資訊；審稿建議改放原則名或分組詞，讓讀者翻到收斂頁之前就看過那六個詞。這會改變「主題：結論」裡主題詞的用法，先不動。
