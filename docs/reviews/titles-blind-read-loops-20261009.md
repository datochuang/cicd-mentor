# 標題盲讀審稿：《為什麼非要 CI/CD》（2026-10-09）

**做法**：同 [titles-blind-read-20261009.md](titles-blind-read-20261009.md)：乾淨 context 的 subagent 只拿文件標題與八頁的頁標題，扮演「每天用 Perforce、熟 PPA 流程、認同方向但懷疑非做不可、不懂 inner/outer loop」的讀者。

**處理**：
- 採用：文件標題改成硬主張並點出對象（「為什麼非要 CI/CD：查和判不交給機器，N 個 agent 等於一個」，kicker 改「CI/CD 的意義」）；「半徑」改「分層」；inner／outer loop 首次出現用中文「內圈／外圈」加英文對照，之後用中文；「行動」改「改動」並舉例（加功能、修 bug）；第 3 頁改「現狀的內圈」；第 6 頁標題寫出 CI/CD 在這裡管的是排隊與固定環境；第 7 頁「連鎖」改「結論」、「倍數歸一」改「N 個 agent 等於一個」；第 8 頁標明六個原則出自《把版控當備份的團隊》，表格改成條件在前、原則在後；第 4 頁說明這裡的「比」是比 PPA 好壞，和第 1 頁的 pass/fail 不同。
- 未採用：把痛點（第 3 頁）移到第 1 頁之前。先定義迴圈再講痛點，是為了讓「每圈要人」這句有所指；懷疑者的硬主張已拉到文件標題。
- 未採用：在第 1–6 頁標題各標出「這是條件之一」。第 8 頁的表格已經把六個條件列出來並指回前面的頁。

## 原始報告（subagent 的話，逐字）

讀者身分：IC 設計部門主管／工程師，Perforce 日常使用者，熟 RTL→sim→synthesis→STA→PPA，對「迭代＋CI/CD」態度是「聽起來不錯，但非做不可嗎？」，不懂 inner/outer loop，沒參與過討論。（依指示未讀任何檔案、未用任何工具，只憑標題作答。）

### A. 光看文件標題，知道是給誰看、讀完要做什麼嗎？

**不知道給誰看，也不知道讀完要做什麼。**

- 「CI/CD 的意義」＋ kicker「為什麼需要 CI/CD」：讀得出這是「說服文」不是操作手冊。這點 OK。
- 「讓迴圈自己轉」：哪個迴圈？我會猜「設計迭代」，但這是猜。IC 流程裡有很多種「圈」（block sim 的圈、regression 的圈、synth/STA 的圈、tapeout 前的 ECO 圈），標題沒指定。
- 「AI 的倍數才成立」：什麼的倍數？產出？人力？速度？這明顯是你們討論裡的簡稱，第一次看會停住。而且它預設我已把「AI 要有倍數」當目標，但我這種讀者的問題是「CI/CD 是不是非做不可」——「才成立」有暗示必要性，但不夠硬。
- 沒有任何字告訴我：這是給主管決定要不要投資源？還是給工程師說服改流程？讀完要我點頭、撥人、還是去看另一份文件？

對「懷疑非做不可」的讀者，真正會打到我的主張藏在第 7 頁（倍數歸一）。建議把那句拉上來當標題，並加一行對象／訴求。

> 建議標題：**為什麼非要 CI/CD：查和判不交給機器，N 個 AI agent 等於 1 個**
> 副標（對象與訴求）：給設計部門主管——決定是否把「查與判」交給機器

### B. 八頁標題連起來，看得出論述順序嗎？哪裡斷掉？

看得出大致骨架：**定義迴圈（1）→ IC 的圈有快有慢（2）→ 現狀的內圈很痛（3）→ 還有一個外圈（4）→ AI 讓「改」變便宜、瓶頸移到「判」（5）→ 平行有上限（6）→ 串起來：沒 CI/CD 倍數歸一（7）→ 對應到六個原則（8）**。

斷掉的地方：

1. **2 → 3 斷。** 第 2 頁說「CI/CD 把它們分層排程」，我期待下一頁說分成哪幾層；結果第 3 頁跳到「沒有 CI/CD 的 inner loop」，冒出新詞，而且方向反過來（從「CI/CD 做什麼」變「沒有 CI/CD 會怎樣」）。我會問：inner loop 是第 1 頁的「迴圈」嗎？是第 2 頁分層裡「最裡面那層」嗎？標題沒答。
2. **順序對懷疑者不利。** 第 1、2 頁先講 CI/CD 做什麼，第 3 頁才講痛點。對「現在這樣也能跑啊」的人，痛點先、解法後比較有說服力。光看標題，「非做不可」的主張要到第 7 頁才出現。
3. **4 的「判」和 1 的「判」不是同一件事。** 第 1 頁的迴圈是「轉到過為止」（pass/fail），第 4 頁 outer loop 比的是「N 個候選的 PPA」（好壞排序）。同一個「判」字指兩種判斷。對 IC 人這差很多：前者是 regression 綠不綠，後者是 PPA 誰贏。
4. **6 → 7 接得鬆。** 第 6 頁後半「比較要在同一環境下才算數」是獨立主張，跟「上限」無關，也沒被第 7 頁的連鎖接走。
5. **7 → 8 斷。** 第 7 頁已是結論，第 8 頁突然出現「六個原則」和「迴圈的一個條件」，兩個名詞前七頁都沒出現過。從標題看，第 8 頁像另一份文件的附錄被貼過來。
6. **整份文件缺一條脊椎。** 標題說「讓迴圈自己轉」，第 8 頁說迴圈有「條件」，但 1～7 頁沒有一頁標題標出「這是條件之一」。如果 1～6 頁其實各在建立一個條件，標題應標出來，第 8 頁的「對應」才站得住。

### C. 哪些標題過度依賴只有寫作者才懂的脈絡？inner loop／outer loop 猜得出來嗎？

依賴內部脈絡的詞，按嚴重程度：

| 詞 | 出現頁 | 問題 |
|---|---|---|
| 六個原則、迴圈的一個條件 | 8 | 指涉另一份文件和一個從未列出的清單，完全無法從本文件推出 |
| 半徑 | 2 | 寫作者的幾何隱喻，讀者沒有線索。IC 人可能誤讀成「影響範圍」(blast radius) 或「跑的 scope」 |
| inner loop | 3 | 第一次出現就當已知詞用，沒定義 |
| 倍數、倍數歸一 | 標題、7 | 「AI 的倍數」是討論裡的概念；「歸一」偏文言，要靠標題才能解 |
| 「改」「查」「判」加引號 | 5 | 依賴第 1 頁的定義；且「查」和「判」對 IC 人的區別不直覺（跑 lint/sim 是查、看 report 決定 pass 是判？） |
| 上限 | 6 | 什麼的上限？要靠第 5 頁的 N 才知道 |
| 連鎖 | 7 | 什麼的連鎖？是「因果鏈」，但字面讀不出 |
| 迴圈 vs loop | 全篇 | 中文「迴圈」和英文「inner loop／outer loop」混用，讀者會問這是不是同一個東西 |

**inner loop／outer loop 猜得出來嗎？** 勉強猜得出，信心「中」，而且主要靠第 4 頁幫忙：

- **outer loop**：第 4 頁標題自己定義了——「比 N 個候選的 PPA，每個候選是一整圈 inner loop」。所以我猜 outer loop = 在 N 個設計方案之間挑 PPA 最好的那一圈。猜得到。
- **inner loop**：第 3 頁只給症狀（人設環境、人跑、人判），沒說它繞的是什麼。我會回推「應該就是第 1 頁的改→查→判」，但有另一個 IC 人很自然的誤讀：**inner = block-level 自己的 sim，outer = full-chip regression／整合**，或 **inner = front-end、outer = back-end**。這個誤讀要到第 4 頁才被排除。再加上第 2 頁的「分層」，我會懷疑「層」是不是就是 inner／outer——標題沒澄清。

建議：首次出現時用中文給對照（「內圈（inner loop）：一個人一個改動的改→查→判」「外圈（outer loop）：N 個方案比 PPA」），之後再用英文。

### 最需要改的前 5 個標題

1. **第 8 頁「對應：六個原則各自撐住迴圈的一個條件」** —— 兩個核心名詞（六個原則、迴圈的條件）在本文件從未出現，等於指著一份讀者沒看過的文件。要嘛把六個條件在前面各頁標出來，要嘛標題至少說原則來自哪裡。
2. **第 2 頁「半徑：…」** —— 「半徑」是只有作者懂的隱喻，IC 人會往 blast radius 或 scope 去想。直接寫「快慢」或「圈有大小」。
3. **第 3 頁「沒有 CI/CD 的 inner loop：…」** —— 這是痛點頁、最該打中懷疑者的一頁，卻用一個沒定義的英文詞開頭。改成「現狀：…」，術語放括號。
4. **第 6 頁「上限：…」** —— 一頁兩個主張（license/算力上限、同一環境才可比），後半跟「上限」無關，也沒說 CI/CD 在這裡扮演什麼。拆開或在標題講清楚 CI/CD 的角色。
5. **文件標題「CI/CD 的意義：讓迴圈自己轉，AI 的倍數才成立」** —— 「迴圈」「倍數」都是內部簡稱，沒有對象、沒有訴求。把第 7 頁的硬主張（N 個 agent 等於 1 個）拉上來，並加一行「給誰、要你做什麼」。

次要但值得順手改：第 7 頁「連鎖」改「結論」、「倍數歸一」改「N 個 agent 等於 1 個」；全篇統一「迴圈／內圈／外圈」與「loop／inner／outer」的對照，首次出現給一次中英對照即可。
