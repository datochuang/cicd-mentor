# 標題盲讀審稿：《為什麼非要 CI/CD》重排成三層脊椎後（2026-10-09）

**做法**：同前幾次。這次只問兩件事：光看十一個標題看不看得出「三層套在一起的迴圈」這條脊椎；每一頁的角色看不看得出。

**處理**：
- 採用：三層正式命名為內圈／中圈／外圈（原本第二層沒有名字，第 5、6 頁讀起來像兩個雜項）；每頁右上角加「第幾層」的標籤，4→5 的換層有訊號；第二、三層的標題補上「機器查過」「機器判過」那一句，讓「CI/CD 在每一層做同一件事」在三層都兌現；「分層」改成「幾道檢查」，不再和「三層」撞字；上限頁標題改成「同時轉幾個方案看 license 與算力；交給機器排，license 才排得滿」；對應頁標題改成「三層各要的條件」，表格每列前面標哪一層，六個條件按層兩兩分組。
- 未採用：第 3 頁寫「lint 幾秒、regression 幾小時」（規則不寫時間數值）；第 11 頁把六個條件逐一列進標題（放不下，表格已列）。

## 原始報告（subagent 的話，逐字）

### A. 脊椎看得出一半

內圈（2–4）和外圈（7）有名字，看得出。第二層沒有名字：5「迭代」、6「交接」都沒標「中圈」或「一個專案」，讀起來是兩個獨立主題，不是一層。整條脊椎盲讀成「內圈 ×3、兩頁雜項、外圈 ×1」，三層不等重：內圈有定義、IC 落實、痛點三頁，外圈只剩一頁定義，中圈連名字都沒有。

「CI/CD 在每一層做同一件事」只在內圈兌現：1、2、3、10 標題都帶「查和判交給機器」，5、6、7 一個都沒有，第二、三層看不出 CI/CD 到底做了什麼。

掉在脊椎外的：9「上限」講 license 與算力，跟查判無關，像插進來的資源規劃頁，也看不出「平行幾個」是幾個方案還是幾個 agent；11「六個條件」前面十個標題沒有一個點名，讀者數不出是哪六個，還引用另一份沒看過的文件。

順序斷點：4→5 從內圈痛點直接跳到迭代，沒有「換層」訊號；8→9 是結論前的岔路。另外「層」一字在 1、8 指三層迴圈，在 3 指按快慢分的檢查關卡，盲讀會混成同一件事。
